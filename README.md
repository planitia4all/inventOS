# InventOS

발명가를 위한 AI 운영체제 — MVP

> InventOS는 "특허 관리 프로그램"이 아니라 "생각이 발전하는 과정을 기록하는
> 시스템"입니다. 아이디어를 저장하는 것보다, 그 아이디어가 시간이 지나며
> 어떻게 발전했는지를 기록하는 것이 더 중요합니다.

## 핵심 사용자 흐름

```text
새 아이디어 빠르게 기록 (메모 한 줄이면 저장 가능, 제목은 자동 생성)
  → 필요할 때 내용 구체화 (해결하려는 문제 / 핵심 원리 / 실험 기록 등)
  → AI로 검토하기 (아이디어 정리 / 기술 검토 / 발전시키기, 12종 원클릭)
  → AI 결과 확인 → 전체 반영 / 일부만 반영 / 보관 / 다시 생성 / 삭제
  → 실험 기록 추가 (조건/결과/실패 원인/개선 아이디어 + 사진·영상 첨부)
  → 이 발명 또는 이 실험에서 파생 아이디어 만들기 (부모-자식 관계 자동 연결)
  → AI 검색어 생성 또는 수동 검색어 입력 → 선행기술(특허) 검색/수동 등록
  → 검색 결과에서 특허 선택 → 발명에 연결 (초록 원문 보관)
  → 같은 점 / 다른 점 / 차별화 아이디어 기록
  → Timeline에서 발전 과정 확인, 필요하면 버전(Revision)으로 되돌아보기
  → Markdown 발명노트 내보내기 / 전체 데이터 백업
```

특허 API 또는 AI API가 설정되지 않아도 발명 기록·AI 검토(Mock)·파생
아이디어·실험 기록·수동 특허 등록·통합 검색·Markdown 내보내기는 모두
항상 정상 동작합니다.

## 발명은 문서가 아니라 "발전하는 객체"

하나의 발명은 아이디어 → 실험 → 문제 발견 → 개선안 → 특허 검토처럼
시간에 따라 계속 발전합니다. 그래서 데이터 모델도 "발명 = 필드가 많은
문서 한 건"이 아니라, 서로 분리된 여러 객체가 하나의 발명 아래 쌓이는
구조로 되어 있습니다.

| 객체 | 역할 |
|---|---|
| `Invention.original_idea` | 최초 원본 메모. AI 정리나 내용 구체화로 절대 덮어쓰지 않는다 |
| `InventionRevision` | 원본/본문을 고칠 때마다(그리고 AI 결과를 반영하기 전) 자동으로 남는 스냅샷 |
| `InventionEvent` (Timeline) | "무슨 일이 있었는지"를 시간순으로 보여주는 자동 기록 (아래 목록 참고) |
| `InventionAIResult` | AI가 만든 결과. 원문·구조화된 항목별 값을 함께 저장하고, 사용자가 '반영'을 눌러야만 발명 내용에 복사된다 |
| `Experiment` | 실험 날짜/조건/결과/실패 원인/개선 아이디어 — 발명 본문과 동등하게 중요한 1급 데이터 |
| `Tag` / `InventionTag` | 중복 없이 관리하는 태그 사전 (문자열을 발명마다 따로 들고 있지 않음) |
| `Invention.parent_invention_id` / `derivation_reason` | 파생 아이디어(부모→자식) 관계와 파생 이유. 예: Separator 접합 → Graphene Fiber 방식(재료 변경) |
| `Invention.source_experiment_id` | 실험 결과에서 파생된 아이디어면 그 실험을 가리킨다 |

### Timeline에 자동 기록되는 사건

발명 생성 · 원본 메모 수정 · 발명 내용 수정 · 상태 변경 · 태그 변경 ·
첨부파일 추가/삭제 · 실험 추가/수정/삭제 · 비슷한 기술 연결/비교기록수정/연결해제 ·
AI 결과 반영 · 파생 아이디어 생성(양쪽 모두) · 보관/보관해제 ·
Markdown 내보내기.

## AI로 검토하기

발명 상세 화면에서 12종의 AI 검토를 그룹별로 원클릭 실행할 수 있습니다.

| 그룹 | 항목 |
|---|---|
| 아이디어 정리 | 아이디어 정리 · 문제점 추출 · 기존 방식의 한계 정리 · 핵심 원리 정리 |
| 기술 검토 | 부족한 부분 찾기 · 기술적 애매점 찾기 · 실현 가능성 검토 · 구현 방법 제안 |
| 발전시키기 | 차별점 찾기 · 실험 계획 제안 · 파생 아이디어 제안 · 특허 검색어 생성 |

- **AI 호출은 항상 DB 쓰기 세션 밖에서 실행됩니다.** 실패해도 발명
  내용·Revision·Timeline에는 아무 변화가 없습니다.
- **결과는 항상 `InventionAIResult`에 별도로 저장됩니다** (원문 텍스트 +
  구조화된 항목별 값 + 사용한 provider/model/입력 스냅샷). 생성만으로는
  발명 내용이 절대 바뀌지 않습니다.
- **같은 항목을 여러 번 실행해도 이전 결과를 덮어쓰지 않습니다** — "1차/2차..."로
  구분해 여러 결과를 비교할 수 있습니다.
- **반영은 사용자가 직접 선택합니다**: 전체 반영 / 일부만 반영(10개 항목
  중 다중 선택) / 검토 결과로 보관 / 다시 생성 / 삭제(소프트 삭제 —
  기본 목록에서만 숨겨지고 실제로는 보존됩니다).
- **반영 전에는 항상 `InventionRevision` 스냅샷이 자동 생성**되고,
  **반영에 성공한 뒤에만** Timeline에 기록됩니다.

### AI 응답 형식 통일

Mock과 실제 Provider(Anthropic 등)가 모두 같은 구조화 형식
(`InventionReviewResult`)으로 응답합니다:

```json
{
  "problem": "", "existing_method": "", "limitations": "",
  "core_idea": "", "working_principle": "", "differentiation": "",
  "expected_effects": "", "implementation": "", "experiment_plan": "",
  "patent_keywords": [], "findings": ""
}
```

"일부만 반영"을 선택하면 이 구조화된 값에서 해당 항목만 정확히
꺼내 반영합니다(예: "핵심 아이디어"를 선택하면 `core_idea` 값만 반영).
AI가 형식에 맞지 않는 응답을 주더라도(JSON이 아니거나 일부 키가
빠졌거나) 프로그램이 멈추지 않습니다 — 누락된 항목은 빈 값으로
채우고, 원문은 항상 `content`에 보존하며, 화면에 파싱 문제 원인을
표시하고, 사용자는 언제든 "다시 생성"으로 재시도할 수 있습니다.

## 파생 아이디어

발명 상세 화면(또는 실험 기록 카드)의 "이 발명에서 파생 아이디어
만들기" 버튼을 누르면 캡처 화면이 파생 모드로 전환됩니다.

- 부모 발명 정보가 배너로 표시됩니다.
- 원본 메모 / 해결하려는 문제 / 핵심 아이디어 / 작동 원리 / 태그 /
  첨부파일 중 무엇을 부모에서 가져올지 선택할 수 있습니다 —
  **기본값은 전부 비어 있어(관계만 연결)**, 필요한 것만 골라야 합니다.
- 파생 이유(구조 개선/재료 변경/작동 방식 변경/문제 해결/비용 절감/성능
  개선/제조 방법 변경/다른 산업 적용/실험 결과에서 파생/기타 + 자유
  입력)를 선택합니다.
- 실험 카드에서 파생하면, 실험 결과를 그대로 저장하지 않고 **편집
  가능한 초안**으로 메모 칸에 미리 채워 넣습니다.
- 생성은 하나의 트랜잭션(부모 연결 + 선택한 내용 복사 + 태그/첨부파일
  복사 + 양쪽 Timeline 기록)으로 처리되어, 중간에 실패하면 전부
  롤백됩니다(부모 관계만 반쯤 만들어지는 일이 없습니다).
- 상세 화면의 "관련 아이디어" 영역에서 부모/자식을 카드로 확인하고
  바로 이동할 수 있습니다.
- 부모를 삭제해도 파생된 자식은 삭제되지 않습니다 — 부모 연결만
  끊어지고(`parent_invention_id`가 `NULL`이 됨) 자식 데이터는 보존됩니다.
  이 동작은 ORM 레벨(SQLAlchemy 관계 설정)뿐 아니라 SQLite FK 레벨에서도
  검증되어 있습니다 — 연결마다 `PRAGMA foreign_keys=ON`을 켜 두고(기본은
  꺼져 있음), 실제로 존재하지 않는 참조를 넣으면 DB가 거부하는지, 부모/
  실험을 삭제해도 FK 위반 없이 자식의 참조만 NULL이 되는지를
  `tests/test_foreign_keys.py`에서 raw SQL로 직접 확인합니다.
- 파생 관계는 `create_child()`가 항상 새로 만든 자식에게만 부모를
  설정하는 구조라서, 기존 발명을 나중에 재부모화하는 기능 자체가 없고
  따라서 순환 관계가 구조적으로 발생할 수 없습니다.

## 기술 스택

- UI: Streamlit
- Backend: Python 3.11+
- Database: SQLite (SQLAlchemy 2.0 ORM) + FTS5 통합 검색
- HTTP: httpx
- 특허 검색: KIPRIS Plus (선택), Mock(데모), 수동 등록 — `PatentProvider` 인터페이스로 교체 가능
- AI: Anthropic Claude (선택), Mock — `AIProvider` 인터페이스로 교체 가능

## 아키텍처: 계층 분리 원칙

지금은 Streamlit 안에서 화면을 그리지만, 나중에 React/Next.js + FastAPI 같은
구조로 옮기기 쉽도록 세 계층을 처음부터 분리해 두었습니다.

```text
src/ui/pages/*.py       ← UI (Streamlit). 화면 조합만 하고 비즈니스 규칙을 넣지 않는다.
src/{도메인}/service.py  ← Business Logic. 검증·트랜잭션·Timeline 기록이 전부 여기 있다.
src/database/models.py  ← Database (SQLAlchemy ORM). 테이블 정의만 담당한다.
```

지켜야 하는 규칙:

- **UI는 서비스 계층만 호출한다.** `src/ui/pages/*.py`는 절대 SQLAlchemy 쿼리를
  직접 만들지 않고, `InventionService`/`PatentService`/`TagService` 같은
  서비스 객체를 통해서만 데이터에 접근한다.
- **서비스 계층은 Streamlit을 모른다.** `src/inventions`, `src/patents`,
  `src/ai`, `src/tags`, `src/timeline`, `src/experiments`, `src/search` 등은
  `import streamlit`을 하지 않는다 — 나중에 이 계층을 그대로 FastAPI 라우터
  뒤에 붙일 수 있어야 한다.
- **DB 세션 하나 = 논리적 트랜잭션 하나.** `src/ui/components/actions.py`의
  `run_and_rerun()`이 "쓰기를 완전히 끝내고 커밋한 뒤에만 화면을 새로고침"하는
  규칙을 강제한다 (Streamlit의 `st.rerun()`을 세션이 열린 채로 부르면 방금
  저장한 내용이 커밋되지 않고 사라지는 문제가 있었다 — 이 헬퍼로 고쳤다).
  파생 아이디어 생성처럼 여러 단계가 필요한 동작도 서비스 메서드 하나
  안에서 전부 처리해, 실패 시 세션 전체가 롤백되도록 한다.

## 설치 및 실행

### 1. Python 설치 확인

Python 3.11 이상이 필요합니다.

```bash
python --version
```

### 2. 가상환경 생성 및 패키지 설치

**Windows (PowerShell)**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. (선택) 환경변수 설정

API 키를 사용하려면 `.env.example`을 `.env`로 복사한 뒤 값을 채워 넣습니다.
API 키가 없어도 프로그램은 정상 동작합니다 (Mock 데이터로 대체).

```bash
cp .env.example .env   # Windows: copy .env.example .env
```

`.env` 주요 항목:

| 변수 | 설명 |
|---|---|
| `INVENTOS_DATA_DIR` | 데이터 저장 경로 (기본값: `./data`) |
| `KIPRIS_API_KEY` | KIPRIS Plus 특허 검색 API 키 |
| `INVENTOS_AI_PROVIDER` | `mock` 또는 `anthropic`. `openai`는 아직 지원하지 않습니다(향후 지원 예정) — `openai`로 설정하면 화면에 안내와 함께 Mock으로 동작합니다 |
| `ANTHROPIC_API_KEY` | Claude API 키 (AI로 검토하기 / 검색어 생성 / 번역 / 요약 / 비교 초안용) |
| `ANTHROPIC_MODEL` | 실제 Anthropic API에서 쓸 수 있는 모델 ID. 예: `claude-sonnet-5`. 비워 두면 화면에 안내와 함께 Mock으로 동작합니다 |

설정 화면(⚙️ 설정 → AI Provider)에서 현재 실제로 어떤 Provider가 동작
중인지, 문제가 있으면 어떤 이유인지 항상 확인할 수 있습니다.

### 4. 실행

```bash
streamlit run app.py
```

브라우저가 자동으로 열리지 않으면 `http://localhost:8501` 로 접속하세요.

기존 DB를 열면 다음이 자동으로 일어납니다(`run_migrations`):

1. 스키마가 실제로 바뀌어야 할 때만, 변경 전 DB 파일을 통째로
   `data/inventos_backup_YYYYMMDD_HHMMSS.db`로 백업합니다(같은 초에 두 번
   백업해도 `_01`, `_02`... 순번을 붙여 서로 덮어쓰지 않습니다). 이미
   데이터가 있는 DB인데 이 백업 자체가 실패하면(디스크 공간 부족, 쓰기
   권한 없음 등) 안전망 없이 스키마를 바꾸지 않고 화면에 원인을 보여준
   뒤 마이그레이션을 중단합니다 — 문제를 해결한 뒤 다시 실행하면 됩니다.
2. 없는 컬럼/테이블을 추가합니다(기존 컬럼 삭제·타입 변경 없음).
3. 예전 상태값·keywords 배열·검색 색인을 새 구조로 옮기거나 다시 만듭니다.

기록은 항상 보존됩니다 — 이 과정에서 기존 발명 데이터가 지워지지 않습니다.

### 5. 테스트 실행

```bash
pytest
```

## 폴더 구조

```text
inventos/
├─ app.py                        # Streamlit 엔트리포인트
├─ src/
│  ├─ config/settings.py         # .env 기반 설정 + 앱 버전
│  ├─ database/
│  │  ├─ models.py                # SQLAlchemy ORM 전체 모델
│  │  ├─ engine.py                # 엔진/세션 생성
│  │  └─ migrations.py            # 컬럼 추가 + 데이터 마이그레이션 + 변경 전 자동 백업
│  ├─ inventions/                 # 발명 CRUD, 원본 보존, 버전 관리, 파생 아이디어
│  ├─ tags/                       # Tag/InventionTag 서비스
│  ├─ timeline/                   # Timeline(InventionEvent) 자동 기록
│  ├─ experiments/                # 실험 기록 서비스 + 파생 초안 생성
```

## 데이터 저장 위치

- `data/inventos.db` — SQLite 데이터베이스
- `data/attachments/<invention_id>/` — 첨부 파일 (사진/스케치/PDF/음성/동영상 등, 파일당 최대 200MB)
- `data/drafts.json` — 작성 중인 내용 임시 저장
- `data/inventos_backup_*.db` — 스키마 변경이 있었던 마이그레이션 실행 전 자동 백업

`data/` 폴더를 백업하면 발명 기록 전체가 보존됩니다. 설정 화면에서도
DB 파일/전체 데이터 ZIP/전체 Markdown ZIP을 바로 내려받을 수 있습니다.

## 백업과 복원

설정 화면(⚙️ 설정)에서 세 가지를 내려받을 수 있습니다.

1. **데이터베이스 파일** (`inventos.db`) 단독 백업
2. **전체 데이터 ZIP** — DB + 첨부파일 전체 + 임시저장(`drafts.json`)
3. **전체 Markdown ZIP** — 모든 발명(보관된 것 포함)을 발명별 `.md` 파일로

두 DB 백업(1, 2번)은 파일을 그대로 복사하지 않고, SQLite의 온라인 백업
API(`sqlite3.Connection.backup()`)로 일관된 스냅샷을 만든 뒤 내려받습니다
— 앱이 실행 중이라 DB에 쓰기가 진행 중이어도 중간 상태가 섞이지 않습니다.

**API 키와 `.env` 파일은 어떤 백업에도 포함되지 않습니다** — 백업 ZIP은
다른 곳에 옮기거나 공유될 수 있으므로 비밀 값은 절대 담지 않습니다.

복원은 별도 기능으로 만들지 않았습니다(실수로 현재 데이터를 덮어쓸
위험이 커서, 이번 단계에서는 백업 제공까지만 범위로 정했습니다). 복원이
필요하면 프로그램을 완전히 종료한 뒤, 내려받은 DB 파일(또는 ZIP을 푼
내용)로 `data/` 폴더를 수동으로 교체하세요.

## Provider 구성

### 특허 Provider (`PatentProvider`)

| Provider | 상태 | 비고 |
|---|---|---|
| Mock | 구현 완료 | API 키 없이 데모 검색 결과 제공 (실제 특허 아님을 명시) |
| 수동 등록 | 구현 완료 | 발명 상세 화면에서 직접 특허 정보(제목/출원·공개번호/국가/출원인/공개일/URL/요약) 입력, AI/KIPRIS 실패와 무관하게 항상 사용 가능 |
| KIPRIS Plus | 구현 완료 (미검증) | `KIPRIS_API_KEY` 필요. 실제 서비스 키로 실시간 검증되지 않았으므로, 사용 전 `src/patents/providers/kipris_provider.py`의 응답 필드 매핑을 재확인하세요 |
| EPO OPS / USPTO | 인터페이스만 존재 | MVP 범위에서 미구현 |

외부 특허 API 호출이 실패해도(`PatentProviderError`) 발명 데이터에는
영향이 없고, 수동 등록으로 계속 진행할 수 있습니다.

### AI Provider (`AIProvider`)

| Provider | 상태 |
|---|---|
| Mock | 결정론적 규칙 기반, 항상 사용 가능. "AI로 검토하기" 12종 전부 지원 |
| Anthropic (Claude) | `ANTHROPIC_API_KEY`와 `ANTHROPIC_MODEL`(실제 API 모델 ID) 설정 시 사용. 모든 응답은 구조화 JSON 스키마로 통일되며, 파싱 실패에도 안전하게 대체 처리된다 |
| OpenAI | 아직 지원하지 않음 (향후 지원 예정). `.env`에 항목만 미리 받아 두며, 지금 `INVENTOS_AI_PROVIDER=openai`로 설정해도 Mock으로 동작하고 화면에 안내가 표시된다 |

AI가 만든 결과는 `InventionAIResult`로 원본과 분리해서 저장되고,
`AIResultService.apply()`를 호출해야만 발명 필드로 복사됩니다. 두 가지
반영 방식은 서로 다르게 동작한다:

- **전체 반영**: AI 원문 전체를 kind별 기본 필드 하나에 채운다.
- **일부만 반영**: 사용자가 고른 항목마다 구조화된 응답에서 정확히
  대응하는 값만 반영한다. 그 항목에 값이 없으면(Mock이거나 파싱 실패)
  원문 전체로 조용히 대체하지 않고 반영하지 않은 채 알린다 — 무관한
  내용이 섞여 들어가는 것을 막기 위해서다.

이미 반영된 결과는 명시적으로 확인하지 않으면 다시 반영할 수 없고,
반영하려는 내용이 이미 그 필드에 있으면(중복) 아무것도 바꾸지 않는다.

## 통합 검색

제목·발명번호·원본 메모·정리된 발명 내용·태그·첨부파일 원본 이름·실험
기록(조건/결과/실패 원인/개선 아이디어)·AI 검토 결과 내용까지 SQLite
FTS5로 한 번에 검색합니다(`src/search/fts.py`).

- 발명 생성/수정, 태그 변경, 첨부파일 추가/삭제, 실험 추가/수정/삭제,
  AI 결과 생성/반영/삭제 시마다 색인을 다시 만듭니다.
- 색인 갱신은 SAVEPOINT로 감싸 핵심 저장 트랜잭션과 분리되어 있습니다 —
  색인 테이블 자체에 문제가 생겨 갱신이 실패해도, 방금 저장한 발명
  내용(핵심 데이터)은 롤백되지 않고 그대로 남습니다. 색인은 언제든
  설정 화면에서 다시 만들 수 있는 파생 데이터로 취급합니다.
- 삭제(소프트 삭제)된 AI 결과는 검색에서 제외됩니다.
- FTS5 쿼리 자체가 실패해도(색인 손상 등) 예외를 던지지 않고 빈 결과를
  반환하며, 상위 계층(`InventionService.search`)이 FTS와 같은 범위
  (발명번호/제목/원본/정리된 내용/태그/첨부파일명/실험 기록/AI 결과)를
  ILIKE로 훑는 대체 검색으로 자동 전환합니다 — FTS 장애 상황에서만
  실행되므로 조금 느려도 정상 검색과 결과 범위가 달라지지 않습니다.
- 기존 DB를 열 때 색인 테이블 구조가 예전 버전이면(컬럼이 더 적음)
  테이블을 다시 만들고 전체 재색인합니다 — 데이터 손실 없이 자동으로
  일어납니다.
- 특수문자만 있는 검색어, 빈 검색어는 예외 없이 처리됩니다.
- 설정 화면(⚙️ 설정 → 검색 색인 관리)의 "검색 색인 검사 및 다시 만들기"
  버튼으로, 부분 손상(일부 발명만 색인 누락/고아 색인/오래된 색인)을
  점검하고 필요할 때만 다시 만들 수 있습니다.

## 법적 안내

본 프로그램의 검색 결과, 유사도 및 AI 분석은 발명 검토를 위한 참고자료입니다.
신규성, 진보성, 권리범위 및 특허침해 여부에 대한 법적 판단을 제공하지 않습니다.
특허 출원 또는 사업화 전에는 변리사 등 전문가의 검토가 필요합니다.

## 삭제 정책

발명 상세 화면의 "보관 / 휴지통"에서:

- **보관하기(권장)**: 목록에서만 숨겨지고 모든 기록(실험/AI 결과/첨부파일/
  Timeline 등)이 그대로 남습니다. 언제든 보관 해제로 되돌릴 수 있습니다.
- **휴지통으로 이동**: 이제 이것이 삭제 버튼의 기본 동작입니다(소프트
  삭제). 확인 절차를 거친 뒤 실행하면 목록/검색 기본 범위에서 숨겨지지만
  실제 데이터는 전혀 지워지지 않습니다 — `deleted_at`만 채워집니다.

설정 화면(⚙️ 설정 → 휴지통)에서 휴지통에 있는 발명을 모두 볼 수 있고,
발명마다 두 가지를 할 수 있습니다:

- **복원**: 휴지통에서 꺼내 목록/검색에 다시 나타나게 합니다.
- **영구 삭제**: 별도의 확인 절차를 거칩니다 — 확인 버튼을 누르기 전에
  함께 사라지는 데이터(실험 기록/첨부파일/AI 결과/선행특허 비교/버전
  기록/Timeline 건수, 그리고 파생된 자식 아이디어가 있으면 그 개수)를
  먼저 보여줍니다. 실행하면 정말로 되돌릴 수 없게 지워집니다. 단,
  **파생된 자식 아이디어 자체는 삭제되지 않고** 부모 연결만 끊어집니다.

보관(`is_archived`)과 휴지통(`deleted_at`)은 서로 다른 개념입니다 — 보관은
"계속 유지하되 목록에서 접어 둠", 휴지통은 "지우려는 의도지만 실수 방지를
위해 즉시 영구 삭제하지는 않음"입니다.

AI 검토 결과의 "삭제"는 이것과 또 다릅니다 — 발명처럼 휴지통을 거치지
않고 바로 소프트 삭제되어 기본 목록에서만 숨겨지고 데이터는 남습니다
(InventOS의 "생각이 어떻게 발전했는지 기록한다"는 철학에 맞춘 선택입니다).

## 알려진 제한 사항

- **작성 중 임시 저장은 서버의 `data/drafts.json` 파일 하나를 씁니다.**
  브라우저 새로고침이나 다른 화면 이동 후 복구는 정상 동작하지만, 여러
  브라우저 탭에서 동시에 "새 아이디어 기록"을 열면 같은 임시 저장 슬롯을
  공유합니다 — 단일 사용자 로컬 프로그램이라는 전제에서는 문제되지
  않지만, 여러 탭을 동시에 쓰는 경우 나중에 저장한 탭의 내용이 우선합니다.
- **파일 첨부는 임시 저장 대상이 아닙니다.** 사진/파일을 선택한 상태에서
  새로고침하면 선택한 파일 자체는 다시 골라야 합니다(텍스트 메모만
  자동 복구됩니다) — Streamlit/브라우저 구조상의 제약입니다.
- **DB 기록과 실제 첨부파일이 어긋나는 경우**(파일 없는 기록, 기록 없는
  고아 파일, 0byte 파일, 내용이 같은 중복 파일)는 설정 화면(⚙️ 설정 →
  첨부파일 무결성 검사)에서 점검 결과를 볼 수 있습니다. 다만 자동
  삭제/정리 기능은 없습니다 — 삭제는 위험할 수 있어 결과만 보여주고,
  실제 정리는 사용자가 직접 판단해서 해야 합니다.
- **동시에 두 개의 발명을 같은 순간 생성하는 경합**은 발명번호 유일성을
  DB의 UNIQUE 제약으로 방어하고, 경합이 감지되면(더블클릭, 여러 탭 등)
  번호를 다시 계산해 최대 3회 자동 재시도합니다 — 사용자에게 원문
  IntegrityError가 보이지 않습니다. 순번을 트랜잭션 락으로 미리 예약하는
  방식은 아닙니다(단일 사용자 로컬 프로그램 규모에서는 재시도로 충분).
- **DB 파일 자체가 읽기 전용이거나 디스크가 꽉 찬 상태에서의 쓰기
  실패**는 각 저장 동작마다 개별적으로 방어되어 있지 않습니다. 이런
  경우 저장 버튼을 눌렀을 때 에러 메시지가 나올 수 있습니다 — 데이터
  저장 경로의 쓰기 권한과 디스크 여유 공간을 확인하세요. (앱 시작 시
  데이터 폴더 자체를 만들거나 쓸 수 없는 경우는 명확한 안내와 함께
  시작이 중단됩니다.)
- **DB 복원 기능은 없습니다.** 백업 파일 다운로드까지만 제공하고,
  복원은 위 "백업과 복원" 절차를 수동으로 따라야 합니다.

## 향후 확장을 위해 준비만 해 둔 것 (UI 없음)

다음은 DB/서비스 구조만 만들어 두고 UI에는 아직 연결하지 않았습니다.
필요해질 때 UI만 추가하면 됩니다.

- **공동 발명자/팀 협업**: `Invention.owner_id`(다중 사용자용 자리),
  `InventionComment` + `CommentService`

승인, 팀 공유, 특허 출원 관리, 일정 관리, 작업 할당 같은 나머지 협업 기능은
아직 구조조차 만들지 않았습니다 — 실제로 필요해지는 시점에 설계하는 편이
과도한 설계를 피할 수 있다고 판단했습니다.

## MVP 범위에서 제외된 기능

React/Next.js·FastAPI 전환, 완전한 PWA(오프라인 동기화), 앱스토어 모바일
앱, 공동 편집, 다중 사용자 권한, 승인 워크플로, 복잡한 관계
그래프/네트워크 시각화, 특허 출원 자동화, 법적 특허성 판정, CAD 파일
내용 분석, 음성 자동 인식, 이미지 OCR 고도화, 알림 시스템, 클라우드
동기화, DB 복원 UI는 이번 범위에 포함되지 않습니다.
